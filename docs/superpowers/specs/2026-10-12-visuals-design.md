# Visuals: HUD colors, custom texts, color fields, Visuals Version

Part 5 of the 2026-10-12 request. Ships in 2.5 beta builds, final in 2.5.

## Goal

Let players change how Dying Light looks (HUD colors, game texts, UV light, Night Hunter glow) with a precise color field everywhere, and offer these cosmetic features as a separate Visuals Version without any cheat, for the FaTrainer launcher and for a Nexus Mods upload.

## Constraints

- No game function on the render thread except the documented exception (Present already calls engine functions for the ESP; HUD color writes follow that precedent because the HUD is drawn on the same thread). Everything else goes through `on_game_thread`.
- Memory through `game::rd/rdv/wr`. No comments in code. All UI text English.
- The Visuals Version contains no cheat code, no ESP, no network code and no launch gate. It must be safe to use in multiplayer: it only changes what the local player sees.

## 1. Visuals Version

- Build flag `FATRAINER_VISUALS`. `build.sh` builds both `xinput1_3.dll` (Fatum Version) and `xinput1_3-visuals.dll` (Visuals Version).
- Code split: UV light, Night Hunter vein colors, the script variable hook (only the vec3 recolor part in the Visuals Version; float scaling stays cheat code), HUD colors and texts live in `src/visuals.h`, included by both builds. `cheats.h` keeps everything else and includes `visuals.h`.
- `FATRAINER_EDITION` is "Visuals Version" in that build (sidebar pill, log, About). A tag `FaTrainer-edition:Visuals` is embedded; the launcher reads it.
- Pages in the Visuals Version: Visuals (without the Player ESP card), Settings (appearance, menu key, About; no configs, no cheat keys, no beta / older version switches). The Keybinds page is absent; the menu key lives in Settings.
- Startup in the Visuals Version: no `launched_from_launcher` gate and no update check. It keeps the crash log, the Present and WndProc hooks and the menu's input blocking (`input.h`), finds the HUD and text objects and applies the saved visuals.
- Release: `release.sh` builds both and uploads `xinput1_3-visuals.dll` and `version-visuals.txt` (same format as `version.txt`) to the same release (and to `beta` with `--beta`). It writes `nexus/FaTrainer-Visuals-<version>.zip` (DLL as `xinput1_3.dll` plus `readme.txt`) for the user's manual Nexus upload.
- Launcher: a segmented control "Full | Visuals only" above Play, saved as `edition=` in `installer.ini`. Play installs the chosen edition when the installed version or edition differs (`logic::needs_install` gets the edition), downloading from the matching files. With Visuals only it does not write `fatrainer.launch` and does not wait for the DLL. Remove from game works for both. Launcher version bump and changelog.
- CLAUDE.md rule: every new or changed visual setting also goes into the Visuals Version and is checked in both builds.
- Self test: the Visuals DLL contains no `CHEATS` keys (e.g. `god`, `one_hit`), no `winhttp` import, and the edition tag; `needs_install` with editions.

## 2. HUD colors

- After every refresh (game thread), find the HUD screen: the `HUDScreenBase` object (`hud.xui` `ClassOverride`, RTTI in gamedll) from the heap scan, through its `IUIElement` base. Keep the root element; drop it on a level change (`respawned`) or when its vtable no longer matches.
- Parts (ids from `data/menu/hud/hud.xui`, picked during planning by reading the file): health bar, stamina bar, crosshair, UV / flashlight bar, XP popups, kill popups, killfeed text, compass / objective text. Each part is a list of element ids, image elements get `IUIElementView::SetColor(vec4)`, text elements `IUIText::SetTextColor(vec4)`.
- Whole HUD tint: walks every element under the HUD root once (`GetChildrenCount` / `GetChildren`), remembers each original color (`GetColor` / `GetTextColor`), sets original × tint, alpha kept. Per-part colors override the tint.
- Applied every frame in Present while any HUD color is on (cheap: a few dozen calls); turning off restores the remembered originals once.
- Config: `hud_tint=on,r,g,b` and `hud=<part>,on,r,g,b`.

## 3. Custom texts

- Hook the engine's localization lookup (the function behind `IUIText::LocalizationCallback`, found during planning) so a key with a replacement returns the user's text.
- The search list comes from `src/texts.h`, generated by `gen_data.py` from `DataEn.pak` `data/maps/common_texts_all.bin` (git-ignored like `items.h`). Featured first: `btz_pounce_interrupted` and the killfeed lines `HUDMessage_BTZDeath_*` / `HUDMessage_BTZZombiePounceInterrupt_*`.
- UI card "TEXTS": search box, results list (key in the small line, text in the big line), a text field for the replacement, Save and Reset per text, Reset all.
- Config: `text=<key>,<replacement>` (replacement escaped: `\n`, `\\`, `,` allowed as-is after the first comma).
- Texts already on screen change when the game asks for them again.

## 4. Color field

- `color_field(id, float rgb[3])` in `menu.h`: swatch that opens an ImGui `ColorPicker3` popup, R G B integer fields (0..255) and a hex field (`#RRGGBB`), returns true on change.
- Replaces every `ColorEdit3` (accent, ESP hunter / survivor, UV light, Night Hunter glow) and is used by every HUD color.

## Error handling

- Missing HUD or text objects: the cards say "Load into the game, then press Refresh" and the log names what is missing (`hud:` / `texts:` lines).
- A HUD element that is gone (vtable mismatch) is dropped, never written.
- The text hook installs only when the expected prologue matches; otherwise the Texts card says it is not available.

## Testing

- Self test: color field conversions (hex parse / format, 0..255 rounding), config round trip of `hud`, `hud_tint`, `text` lines with commas and newlines, tint math (original × tint, alpha kept), HUD part lookup on a fake element tree, the text hook returning replacements on a fake table, Visuals DLL content checks, `needs_install` with editions.
- Preview: Visuals page in both editions, Settings in the Visuals Version.
- Live (user): HUD colors in story mode and Be The Zombie, texts (pounce interrupted, killfeed), the launcher switch.

## Out of scope

- Other players do not see HUD colors or texts (by design).
- Menu skins beyond the existing appearance settings.
