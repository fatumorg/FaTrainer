# Visuals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Color fields with picker, RGB and hex everywhere; HUD colors (whole HUD tint and per part); custom game texts; a Visuals Version (cosmetic only, no cheats, no network) offered by the launcher and zipped for Nexus.

**Architecture:** Cosmetic code moves into `src/visuals.h`, shared by the Fatum build and a new `FATRAINER_VISUALS` build. HUD colors go through engine UI exports on the `HUDScreenBase` object found by the heap scan; texts go through a hook on the engine's localization lookup, with the searchable list generated by `gen_data.py` into git-ignored `src/texts.h`. The launcher gets an edition switch and installs `xinput1_3-visuals.dll` from the same releases.

**Tech Stack:** C++17, mingw-w64, Dear ImGui 1.91.9, GLFW launcher, bash release scripts, python + capstone for disassembly.

**Spec:** `docs/superpowers/specs/2026-10-12-visuals-design.md` (deviation: the text search list comes from `src/texts.h` generated from `DataEn.pak` `common_texts_all.bin`, not from the engine's table at runtime).

## Global Constraints

- No comments in any file. Names explain the code.
- Product name `FaTrainer | Dying Light`; UI text English.
- Memory through `game::rd`, `game::rdv`, `game::wr`; never `ReadProcessMemory`.
- Game functions only on the game thread (`on_game_thread`), except UI color writes in Present, which follow the ESP precedent (Present runs on the window thread that draws the HUD).
- Game-derived data out of git: `src/texts.h` is generated and git-ignored like `items.h`.
- After every finished task: `./build.sh`, self test, preview when the UI changed, check `imgui assert` in `test/fatrainer.log`, commit and push to `origin main`, update `PROGRESS.md`, check `site/`.
- Commits as the configured git user, no attribution trailers.
- Builds: Visuals features ship in `2.5 b3`, `2.5 b4`, ... (beta), version name stays `Survivor Update`.

## Review Focus

1. HUD element pointers after a level change or respawn: never write to a dead element (vtable check before every write; drop all on `cheats::respawned`). Test in Task 4.
2. Text replacements with commas, `=`, newlines and non-ASCII characters must survive a save and load. Test in Task 2.
3. Hex input with or without `#`, lowercase, 3 digits or garbage must not change the color unless valid. Test in Task 1.
4. A missing HUD (main menu, loading screen) must not crash or spam the log; the card shows a hint. Test in Task 4 (fake tree with no HUD).
5. The Visuals DLL must not contain cheat code or WinHTTP. Test in Task 6.

```cpp
#pragma once
#include <algorithm>
#include <cmath>
#include <cstdio>
#include <string>

namespace color {

inline int to_byte(float v) { return (int)std::lround(std::clamp(v, 0.0f, 1.0f) * 255.0f); }

inline std::string to_hex(const float rgb[3]) {
    char b[8];
    snprintf(b, sizeof b, "#%02X%02X%02X", to_byte(rgb[0]), to_byte(rgb[1]), to_byte(rgb[2]));
    return b;
}

inline bool from_hex(const std::string& text, float rgb[3]) {
    std::string digits = !text.empty() && text[0] == '#' ? text.substr(1) : text;
    if (digits.size() != 6 || digits.find_first_not_of("0123456789abcdefABCDEF") != std::string::npos) return false;
    unsigned long v = strtoul(digits.c_str(), nullptr, 16);
    rgb[0] = ((v >> 16) & 0xFF) / 255.0f, rgb[1] = ((v >> 8) & 0xFF) / 255.0f, rgb[2] = (v & 0xFF) / 255.0f;
    return true;
}

}
```

Engine pieces (engine exports, resolved with `GetProcAddress` on `engine_x64_rwdi.dll` in `cheats::locate_engine`):
- `?FindElement@IUIElement@@QEAAPEAV1@AEBV?$string_base@D@ttl@@_N@Z` (this = `IUIElement*`, name = ttl string whose first member is `const char*`, recursive bool).
- `?GetChildrenCount@IUIElement@@QEAAHXZ`, `?GetChildren@IUIElement@@QEAAPEAV1@H@Z`.
- `?GetColor@IUIElementView@@QEBA?AVvec3@@XZ` is vec3 only; colors are read once from the element as vec4 through `?GetTextureColor@IUIElementControl@@QEAA?AVvec4@@H@Z` where available, otherwise the original is remembered from the first `GetColor` with alpha 1.
- `?SetColor@IUIElementView@@QEAAXAEBVvec4@@@Z`, `?SetTextColor@IUIText@@QEAAXAEBVvec4@@@Z`, `?GetTextColor@IUIText@@QEAA?AVvec3@@XZ`.
- Class checks with `game::base_offset(engine, vtable, "IUIElementView")` / `"IUIText"`: write a color only when the element's RTTI has that base; the offset is added to the element pointer.
- The HUD root: the `HUDScreenBase` object (RTTI in gamedll) found by `game::scan`; its `IUIElement` base through `game::base_offset(gamedll, vt, "IUIElement")`.
